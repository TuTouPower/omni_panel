# p227 macOS 宿主下三处测试仍按 Linux 平台假设断言

- 现象：macOS（darwin）上跑 `pnpm test`，同一份代码下有 3 个既有用例失败：`collector-local.test.ts` 两个（期望 `sessions[0].env==="linux"`、`sources_status` 找 `env==="linux"` 的 `claude_code`，实际 `env==="mac"`）、`client.test.ts:189` 一个（`autostart 在 Linux 返回 unsupported` 期望 exit 0，macOS 走 electron 分支返回 1）、`net-client.test.ts:447` 一个（`allows reading symlink pointing inside allowed directories` 拒绝，报 `symlink target outside allowed directories`）。
- 影响：macOS 本机 `pnpm test` 恒红，pre-push hook（`pnpm typecheck && pnpm test`）阻断推送；开发者被迫 `--no-verify`。功能面：`autostart` 在 macOS 实际走 electron `setLoginItemSettings`（`src/main/cli/client.ts:232` 只判 `linux`），语义正确、无生产 bug；net-client 为 fail-closed（拒绝），无安全回归。
- 根因：项目由 WSL/Linux 迁 macOS（`0192640f`）后，测试内嵌的宿主平台假设未更新。(1) `collector-local.test.ts:79`/`:195` 两例未显式 `set_collector_host("linux")`，依赖 `host_from_platform(process.platform)`（`paths.ts:29`，darwin→macos），故 env 标签为 `mac`；同文件其余用例（`:146`/`:288`/`:344`/`:397`）已显式注入 host 才过。(2) `client.test.ts:189` 断言写死 Linux 文案与 exit 0，未按 `process.platform` 分支或 mock `platform`。(3) macOS `os.tmpdir()` 返回 `/var/folders/...`，其 realpath 为 `/private/var/folders/...`；`net-client.ts:486` 先以未 realpath 的 `resolved_path` 过 `is_within_allowed`，`:493` 再对链接做 `realpath` 并以同一 `allowed`（未 realpath 的 temp_dir）比对，realpath 后落在 `/private` 下即判 outside，误伤「允许目录内」的链接。同类位点：以上 3 处；其余 `env:"linux"` 出现处（renderer/shared/session-state 等 20+ 文件）均为显式数据字面量、不依赖宿主，已扫无同类。
- 测试缺口：三例都以「本机即 Linux」为前提，未覆盖 darwin。补法：collector-local 两例显式 `set_collector_host("linux")`（与同文件既有用例对齐）；client autostart 例按平台分支断言（Linux 文案/exit 0 vs macOS 走 electron 经 mock）或抽出平台判定；net-client 允许目录用 `realpathSync(temp_dir)` 作白名单根。验证命令：`pnpm test` 于 darwin 下全绿。
- 线索：`.scratch/` 下 `pnpm test` 复现；失败栈见 `tests/unit/main/core/token-stats/collector-local.test.ts:107`、`tests/unit/main/cli/client.test.ts:205`、`tests/integration/connector/net-client.test.ts:464`。
