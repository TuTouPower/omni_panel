# Task spec

## 背景

连接器通用执行基座（`net-client.ts`、`runtime.ts` 与相关辅助模块）存在多维度的健壮性与架构问题：大响应体全量拼接内存放大；本地文件读写存在软链逃逸隐患；错误排障信息缺失；重试逻辑缺乏错误类别辨别；多实例冷却存在误伤；CPA 等 20 个连接器存在重复的阈值计算副本；参数泥团与无界缓存缺乏治理。

## 契约区

### 范围

- `net-client.ts` 响应体上限下调至 10MB，并在流读取过程中超限立即 abort；非 2xx 错误响应脱敏保留前 500B 用于排障；超时参数支持配置化与非法值保护。
- 本地文件读写与遍历引入真实路径解析（`realpath`）与安全沙箱断言；遍历设置数量上限（5000）并并发化。
- 引入不可重试错误基类，对 4xx、语法及编译错误短路重试流程；强化超时与 abort 归因；保留调用栈信息。
- Probe 模块在空 header 或空推导时抛出明确异常；记录多头匹配日志。
- 将冷却（cooldown）状态绑定到 `source_instance_id`，隔离同一连接器的多账号实例。
- 重构 `perform_request` 为参数对象；保留多值 Header；收敛内部安全函数导出；清理 `host-io.ts` 冗余字段。
- 运行时环境通过 `ctx.util` 统一注入阈值与百分比工具，消除 20 个连接器内的重复工具代码。
- 脚本缓存接入 LRU(50) 淘汰策略与并发 inflight 去重；观测数据引入校验 fast-path。
- 连接器外部输入边界接入 zod `safeParse` 防御；统一 provider 权威来源为 manifest。

### 非范围

- 不替换底层 `node:vm` 运行时引擎（留至 t515 独立实施）。
- 不破坏连接器既有的对外输出结构契约。

### 验收标准

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：请求遇到超过 10MB 的响应流时立即中断连接并抛错，不发生全量内存拼接。
- [ ] AC-002：解析包含软链指向目录外部的本地文件请求时被拒绝；目录遍历支持并发且遇到超大目录时在 5000 项安全截断。
- [ ] AC-003：接口返回 4xx 状态码或抛出代码语法异常时，不执行剩余 2 次多余重试，立即报告失败并附带脱敏后的响应片段。
- [ ] AC-004：某个账号实例因超时进入冷却状态时，同配置的其他账号实例仍可独立发起采集与刷新。
- [ ] AC-005：连接器可通过 `ctx.util` 访问共享阈值与工具函数，各连接器内部不再包含重复的私有计算逻辑。
- [ ] AC-006：`script-cache` 在高并发或超过 50 个脚本时正确执行去重与 LRU 驱逐。
- [ ] AC-007：各连接器对外部网络返回的非规范 JSON 数据通过 zod 校验拦截，不发生直转引发的运行时异常。

### 风险与回退

- 风险：若个别连接器依赖了旧的未严格校验字段，zod 边界收紧可能暴露隐性不兼容。
- 回退：按连接器逐批接入并运行现有集成测试回归；必要时对特定字段增加宽松兼容。
