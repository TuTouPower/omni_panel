# Task spec

## 背景

当前 `src/preload/index.ts` 中存在 40 行三栈复制逻辑以及 144 行硬编码 route 表，导致各窗口暴露能力不均且难以审计。低权窗口（如 popup、tray、session）暴露了过多管理能力；Popup 窗口在调用 `config.save` 持久化自身展开/排序状态时，未限定修改字段，具备写全量配置的潜在权限。按干净架构要求，应将其重构为数据驱动的路由工厂与细粒度分权矩阵。

## 契约区

### 范围

- 抽象 `base + withDisabled` 能力工厂与数据驱动 route 映射表。
- 区分 readonly 与 settings 窗口能力档位，针对 popup/tray/session 等低权窗口仅注入最小必要能力集。
- 对 Popup 暴露的 `config.save` 施加字段白名单校验，仅允许修改 UI 相关字段，其余字段被过滤。
- 编写 Preload 权限矩阵单元测试，显式断言各窗口的能力暴露面。

### 非范围

- 不修改主进程内部已有的 IPC 处理逻辑。
- 不更改现有前端页面的 IPC 接口调用签名。

### 风险与回退

- 风险：白名单字段若遗漏了某个已有的前端 UI 持久化键，可能导致该 UI 状态不保存。
- 回退：全面盘点 Popup 当前使用的全部键（如 providerOrder、accountOrders、collapsedAccounts 等），如有遗漏及时补齐；必要时代码回退。
