# Task spec

## 背景

p263：Muse 连接器 `resolve_dynamic_action_ids()` 在无法走基准部署捷径时，先把首页提取到的全部首屏脚本串行 `await ctx.http.get_raw()` 下载完（`connectors/muse/connector.ts:132-142`），再扫描 `fetchSubscriptionAction`（`:145`），命中也不早停；异步分包（`target_chunks`，`:185`）同样串行。实测 107 次 GET、累计 27006ms 才解析出 Action ID，用量 POST 到 27535ms 才发出，超过隔离宿主 15s 预算被硬杀（`Connector execution timeout after 15000ms`），连续三次后两条观测被标 stale。每轮刷新（30s）与每次重试都重算，持续压站。

本 task 在 t528（统一执行预算 / 协作取消 / 有界并发）与 t529（类型化发现缓存 `ctx.discovery`）基础上重写 Muse 动态发现与采集：主路径走构建清单定位分包、命中即停、有界并发、按签名复用发现结果、为用量采集预留预算。依审阅结论（A/C）：**删除 BASELINE 静默回退**——不再拿历史硬编码 Action / Deployment ID 掩盖部署漂移或发现失败；显式参数降级为独立手动 / debug 逃生模式。t525 已修复动态 Action ID 提取语义，但未覆盖真实请求规模与预算关系，本 task 补上该验收。

## 契约区

### 范围

- 删除 `BASELINE_ACTION_ID` / `BASELINE_DEPLOYMENT_ID` 静默回退：无法确认部署或发现失败时显式失败，不套用历史 ID、不把发现失败伪装成其他错误。`ACTION_ID` / `DEPLOYMENT_ID` 参数仅保留为显式手动 / debug 逃生模式，不作正常路径。
- 重写 `resolve_dynamic_action_ids()`：主路径走构建清单定位 settings 分包；边下载边扫描、命中即停；分包下载有界并发经济宿主原语；用量 POST 预留预算。
- 签名 = `deployment_id` + 首页脚本清单 hash；命中 `ctx.discovery` 缓存时跳过全部分包下载（仅 1 次首页校验）。
- 失败发现永不写缓存；收到 404 / Invalid Server Action 必使缓存失效并重发现。
- 结构化错误分类：`SESSION_EXPIRED`（映射重登）/ `ACTION_STALE`（映射重发现）/ `BUDGET_EXHAUSTED`（映射告警）/ `DISCOVERY_EMPTY`。
- 阶段性日志：阶段、请求数、耗时（不记 Cookie / 页面正文）。
- 测试按 p263 实测分布 pin 延迟（首页约 1.3s、分包均值约 250ms、107 个分包），覆盖提前命中 / 无命中 / 单包 404 / 慢包 / 签名变化 / 缓存投毒。

### 非范围

- 不改宿主预算 / 取消 / 缓存底座（t528 / t529）。
- 不修改其他连接器（统一宿主约束由 t528 覆盖；本 task 脚本改动仅限 Muse）。
- 不承诺 Cookie 永不过期，也不承诺未来任意网页部署结构都可解析。

- [ ] AC-001：当靠前分包已含目标 Server Action 引用时，发现在命中后立即停止，不再下载其余分包（以请求数 / 阶段日志可观察）。

- [ ] AC-005：服务端以 404 / Invalid Server Action 拒绝时，缓存失效且错误以 `ACTION_STALE` 标识，下一轮重新发现。
- [ ] AC-006：在 107 分包、首页约 1.3s、分包均值约 250ms 的模拟下，发现与用量阶段均在宿主预算内完成，产出至少两条用量观测；用量 POST 不因发现阶段耗尽预算而无法执行。
- [ ] AC-007：发现失败、单分包 404、慢响应均可产生可诊断错误（结构化错误码）；日志不含 Cookie 与页面正文。
- [ ] AC-008：发现失败且无显式手动参数时，不再静默套用历史 Action / Deployment ID，而是以 `DISCOVERY_EMPTY` 显式失败。
- [ ] AC-009：会话失效仍以 `SESSION_EXPIRED` 识别并可触发重登，不因去除 baseline 而退化。
- [ ] AC-010 [deploy]：打包应用对 Muse 真实刷新成功产出用量观测，单次刷新耗时较 p263 记录的 27s 发现阶段显著缩短且不再触发 15s 超时。

## 上下文区

- 来源：p263（核实 2026-09-27：串行 107 GET 约 27s，超 15s 预算；t525 已修语义未覆盖规模）；审阅意见 A/C（删静默 baseline 回退、结构化错误码、AC 硬阈值）。

### 有意不测

- Cookie / 会话长期有效性：超出范围，不做时效契约断言。
- 未来任意网页部署结构的可解析性：仅覆盖当前与模拟结构。

### 测试策略

- 集成：在 t528 测试缝上按 p263 分布模拟（107 分包 / 首页约 1.3s / 均值约 250ms），断言命中即停、并发上限、预算内完成、>=2 观测；单包 404 / 慢包 / 无命中的错误可诊断性。
- 缓存：命中复用（分包 GET=0）、签名变化失效、action 过期失效后重发现、缓存投毒（失败发现不写缓存）。
- 日志：断言阶段 / 请求 / 耗时可见且不含 Cookie / 正文。
- 回归：现有 `tests/integration/connector/muse_connector.test.ts` 的解析 / 认证语义测试保留；因去除 baseline 而失效的用例按新语义新增覆盖，旧用例整体删除并写明理由，禁止就地把预期改成当前输出。
- [deploy] 真实刷新：按项目规则先取得打包 / 重启许可后人工核实 AC-010。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- Muse 当前部署是否提供稳定的构建清单 / 部署标识（如 `_buildManifest`），可替代「下载全部分包再扫描」的结构性降耗：`UNVERIFIED-SPIKE`，待验证方式为真实探针抓取首页与构建清单，确认可定位 settings 分包；不可用则退回「命中即停 + 有界并发 + 缓存」路径，不阻塞本 task。
- Muse Action 失效响应的稳定判别信号（404 / Invalid Server Action）：`UNVERIFIED-SPIKE`，以现有代码与真实探针确认判别式；t525 已部分覆盖。

### 风险与回退

- 风险：去除 baseline 静默回退后，无法确认部署 / 发现失败时 Muse 将显式失败（不再尝试历史 ID）。这是刻意的可用性取舍：历史 ID 在部署漂移时本就会触发 `MUSE_ACTION_STALE`，且会掩盖发现失败。
- 风险：Muse 网页结构或分包命名变化使解析失败；并发下载引入瞬时压力；缓存复用旧 Action 掩盖发现失败。
- 回退：运行时回退靠 git revert（无运行时开关）。业务上：显式参数手动模式保留为逃生路径；action 失效信号必使缓存失效，禁止旧 ID 永久掩盖失败。
- 风险：AC-010 依赖真实站点，可能因站点变化无法一次通过；[deploy] 验证失败不阻塞其余 AC，记录为遗留并按需重试。

### 依赖与约束

- 前置：t529（并传递依赖 t528）。
- 约束：不得记录 Cookie / 页面正文；不得降低对会话失效的识别；并发不得无上限；缓存不得存 secret；不得恢复历史 Action / Deployment ID 静默兜底。
- 平台：Windows / macOS / Linux 一致。
