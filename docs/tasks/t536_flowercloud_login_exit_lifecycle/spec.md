# Task spec

## 背景

p269 记录：用户未处理花云登录时整应用退出。日志已确认 2026-09-29T21:26:51 应用走了整体有序退出（macOS 统一日志 `voluntary`、无崩溃报告），但**退出请求来源未定位**：静态分析已列出菜单、托盘、控制 API、`will-quit` 清理、启动失败 `app.exit(1)` 等入口，均未建立「花云未登录 → 退出」调用链；同时 `window-all-closed` 是空处理器、面板 `hide()` 只隐藏窗口。因此当前缺的是「可追溯的退出来源」与「花云会话异常不得影响进程存活」的保证和回归。

## 契约区

### 范围

- 退出入口来源可追溯：应用内每个显式退出入口记录来源标识与 trace，使日志能回答「谁请求了退出」。
- 花云会话异常隔离：未完成登录、不操作、取消、关闭验证 / 登录窗口、超时五种情况只影响花云实例。
- 生命周期回归：主进程存活、托盘可用、主面板可重新唤起、其它连接器刷新不中断。
- 焦点与面板状态组合：验证窗获焦时 popup / 浮窗 / 钉住三种主面板状态的既定行为被测试固定。
- 若定位到根因则修复；否则交付可追溯观测能力与已排除清单。

### 非范围

- 不改花云取数的后台优先策略与窗口可见性（t535）。
- 不重构主面板隐藏逻辑（除非确认缺陷）。
- 不做打包 / 发布流程改造。

- [ ] AC-001：应用内所有显式退出入口（`app.quit()` / `app.exit()`，创建时扫描到 12 处，清单见「上下文区 · 显式退出入口」）在日志中写入可区分的来源标识与同一 trace，可据此判定退出请求方。
- [ ] AC-002：花云未登录且用户不操作、等待预算耗尽后，主进程存活、托盘可用、主面板可重新唤起、其它连接器刷新不中断。
- [ ] AC-003：用户取消或手动关闭花云验证 / 登录窗口，只结束该会话（窗口关闭、登记释放），不触发应用退出。

### 有意不测

- 崩溃类退出：本现象已确认为有序退出且无崩溃报告，不覆盖。
- 打包安装器 / 更新流程相关退出路径：与本次现象无关。

### 测试策略

- 入口来源测试：逐一触发退出入口（以可注入方式），断言日志来源字段与 trace 关联。
- 会话生命周期集成测试：不登录 / 取消 / 关闭 / 超时四种场景断言不调用退出 API、登记释放、其它实例刷新继续。
- 焦点组合测试：验证窗获焦 + popup / 浮窗 / 钉住，断言面板可见性与进程存活。
- 真机：AC-005 人工核验一次完整链路，记录 trace。

### 风险与回退

- 风险：来源埋点覆盖面不足，下一次同类事件仍无法定位；调整焦点组合行为时误伤面板隐藏体验。
- 回退：埋点为纯增量日志字段，可独立 revert；行为修复按 commit 粒度回退。

### 依赖与约束

- 依赖 t535 对花云窗口 / 登记语义的收敛，避免两处同时修改窗口生命周期。
- 需要 `test:e2e:electron` / 打包版观察时必须取得用户许可。
- 不得为定位而引入生产环境的自动退出或重启行为。
