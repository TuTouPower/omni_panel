# Task spec

## 背景

Muse 连接器通过动态扫描 Next.js 页面与异步分包嗅探 `fetchSubscriptionAction` 的 Server Action ID。在当前真实前端分包中，存在多个 `HatchSettingsDialogContent` 模块候选（如候选 `273187` 关联分包无目标，候选 `862035` 关联分包才包含目标）。

当前生产实现仅在未赋值时记录首个完成下载的候选（`if (!settings_module_id)`），且在对应分包未找到目标后直接报错 `DISCOVERY_EMPTY`，没有遍历回退到其他候选。此外，由于 `ctx.pool.map` 按完成顺序 yield，网络时序波动会导致错误候选先到即被锁定，导致用量无法刷新并在重试后耗尽预算（`p266`）。需要修复多候选发现与回退机制，确保不受并发响应顺序影响。

## 契约区

### 范围

- 重构 `connectors/muse/connector.ts` 的 `resolve_dynamic_action_ids`：
    - 将单一候选锁定机制升级为**多候选列表收集与逐一验证回退**，首个候选未找到目标时继续验证后续候选模块，直到命中目标或候选穷尽。
    - 消除并发响应完成顺序带来的非确定性：在首屏脚本扫描完毕后，对提取到的候选模块按确定性顺序或聚合清单依次排查关联分包。
    - 在未发现目标时输出带已检候选数、已检分包数与耗时的结构化诊断日志，便于追踪。
- 测试覆盖与防回归：
    - 在 `tests/integration/connector/muse_connector.test.ts` 补充真实多候选回归用例（模拟两个候选模块：错误候选先到、正确候选后到，以及响应顺序置换），断言连接器均能成功回退并解析出正确 Action ID。
    - 确保 `pnpm test` 与类型检查 100% 通过。

### 非范围

- 不改变 Next.js Server Action 调用的请求协议与参数格式。
- 不引入跨会话持久化存储破坏或修改已有 `ctx.discovery` 接口。

## 上下文区

- 来源：`p266`（2026-09-28 核实，定位至 `connectors/muse/connector.ts` 中 `settings_module_id` 首候选锁定且无回退机制）。
- 关联任务：`t508`（初始接入）、`t525`（动态嗅探）、`t528`（执行预算）、`t529`（持久化缓存）、`t530`（并发与缓存重构）。

### 有意不测

- 外部 Muse 网站在生产网络环境下的频繁发布与动态混淆（通过脱敏离线多候选 fixture 模拟覆盖）。

### 测试策略

- 多候选时序置换集成测试：构造包含模块 A（无目标分包）与模块 B（含 `fetchSubscriptionAction` 分包）的脱敏测试用例，分别模拟 A 先完成与 B 先完成两种请求时序，验证 AC-001 与 AC-002。
- 候选穷尽失败测试：构造所有候选均无目标的测试用例，断言抛出 `DISCOVERY_EMPTY` 并验证诊断日志。
