# Task spec

## 背景

会话库当前用"加载更多"按钮手动翻页（`SessionLibrary.tsx` `load_more`），用户希望移除按钮，改为滚动到底自动加载下一页（无限滚动）。同时保持网格/列表卡片尺寸固定、随窗口而非随内容缩放（卡住修复见 t327）。

## 契约区

### 范围

- `src/renderer/components/session-library/SessionLibrary.tsx`：移除"加载更多"按钮（含 `loading_more`/`can_load_more` 渲染分支），改为容器滚动触底自动加载下一页。
- `src/renderer/components/session-library/SessionList.tsx`：网格/列表滚动容器暴露滚动事件给父组件，供触底检测。
- 复用现有 `load_more` 数据拉取逻辑（offset 分页、`has_more` 终止），仅改触发方式。

### 非范围

- 不改服务端 `/v1/sessions` 分页接口、数据模型。
- 不改卡片尺寸/内容（t327 负责）。
- 不做虚拟滚动（仅本 task 需求：滚到底加载）。

- [ ] AC-001：会话库不再渲染"加载更多"按钮（网格与列表视图均无）。
- [ ] AC-002：滚动到会话列表底部时自动加载下一页，列表追加新会话，无需点击。
- [ ] AC-003：全部会话加载完（`has_more=false`）后，滚到底不再发起请求（无重复请求、无报错）。
- [ ] AC-004：加载进行中再次触底不并发重复请求（同一时刻仅一个加载请求在途）。
- [ ] AC-005：切换筛选/搜索/排序/翻页重置后，无限滚动状态与首屏一致（触底继续加载、`has_more` 重置）。
- [ ] AC-006：网格与列表两种视图下无限滚动行为一致。

### 测试策略

<!-- 规范（门禁必留，不得删除） -->

mock 边界、fixture 来源、断言目标。无特殊约定写「按项目默认」。

- web e2e（playwright）驱动真实浏览器：加载首屏 → 滚到底 → 断言新请求发出且卡片数增加 → 再滚到底（has_more 后）断言无请求。
- fixture 用合成数据（`tests/e2e` 现有 synthetic 模式）。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

尚未核实的外部 endpoint、API 形态、数据结构、第三方行为须分类标记；核实后删除标记，改为结论并注明验证方式。无则写「无」。

<!-- /规范 -->

- 滚动容器在 web 端与 Electron 端是否一致：`SessionList` 的滚动容器两平台同源，执行期验证 `UNVERIFIED-SPIKE`（浏览器实测滚动触发）。

### 风险与回退

- 风险：滚动监听在 React StrictMode 双挂载下重复注册/泄漏；content 搜索模式（`content_sessions`）分页语义与后端 offset 混用，滚到底可能误触发。已识别，执行期对 `content_mode` 分支复用现有关闭逻辑。
- 回退：撤销 `SessionLibrary.tsx`/`SessionList.tsx` 改动，恢复按钮。

### 依赖与约束

- t327（卡片高度修复）应先于或同批合入，否则无限滚动后卡片仍压扁，无法验收。
