# Task spec

## 背景

按最干净架构与最好设计标准，系统存在结构性技术负债：三大上帝文件（`index.ts`、`server.ts`、`token-stats-store.ts`）各自长达 1500~2000 行，将启动编排、路由、数据存储与迁移紧密耦合在一起；全仓存在大量不符合编码规范的 kebab-case 与 PascalCase 文件名；架构边界依赖检查规则过于单薄；存在 `lodash` 等未消费死依赖。

## 契约区

### 范围

- 卸载 `lodash` 死依赖并清理包配置文件。
- 完善 `.dependency-cruiser.cjs`，补充连接器、渲染层、IPC 与本地服务的架构边界约束。
- 模块化拆分 `src/main/index.ts`（按引导、CLI 入口、配置编排等拆分）。
- 模块化拆分 `src/main/core/local-api/server.ts`（按路由域拆分为子路由文件）。
- 模块化拆分 `token-stats-store.ts`（按流水记录、聚合 rollup、报表面板与迁移拆分）。
- 全仓统一文件与目录命名为 `snake_case`，保持测试镜像结构对齐。
- 梳理 `src/main/core` 目录职责边界。

### 非范围

- 不变更任何既有业务逻辑、API 返回结果或配置持久化格式。
