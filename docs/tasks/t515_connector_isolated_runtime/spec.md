# Task spec

## 背景

当前系统使用 `node:vm` 执行连接器脚本，由于 Node.js 的 vm 模块并不防范恶意逃逸，连接器脚本存在潜在逃逸并直接控制 Electron 主进程的高危风险。在审阅决策中，用户已确定采用彻底隔离的架构方案：将连接器执行移至独立进程隔离环境（utilityProcess），建立内置连接器的 SHA-256 完整性校验清单，并在过渡阶段默认仅信任内置连接器，从根本上杜绝主进程 RCE 隐患。

## 契约区

### 范围

- 设计并实现基于 Electron `utilityProcess` 的独立连接器隔离进程宿主。
- 主进程与连接器工作进程之间建立结构化消息通信协议，仅传递经过序列化的参数与采集结果。
- 在构建/打包阶段为内置连接器生成 SHA-256 清单，加载时校验哈希，不符则拒绝执行。
- 默认禁止加载未受信的用户外部目录连接器，必须经由用户显式配置信任。
- 编写针对隔离进程崩溃重启、超时终止、逃逸防护及 20 个连接器的功能回归测试。

### 非范围

- 不修改现有连接器面向用户的 UI 呈现形式。
- 不影响主面板其他无关进程（如渲染视图进程）。

### 测试策略

- 单元测试：哈希清单生成与校验逻辑测试、外部连接器策略过滤测试。
- 集成测试：启动独立工作进程并执行真实连接器采集任务，验证跨进程 IPC 协议正常交互。
- 破坏性测试：模拟工作进程 crash 与无限循环，验证主进程的自动恢复与任务超时熔断。

### 风险与回退

- 风险：utilityProcess 在特定精简平台环境可能存在 IPC 延迟或打包路径寻址差异。
- 回退：如果进程间通信带来显著延迟或平台问题，可通过特性开关回退到沙箱隔离模式。

### 依赖与约束

- 依赖 Electron 提供的 utilityProcess API。
