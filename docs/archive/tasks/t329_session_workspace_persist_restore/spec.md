# Task spec

## 背景

会话工作台打开的会话卡片存在 `slots_state`（`useWorkspaceColumns` 的 `useState(empty_slots)`），纯内存态。窗口重开 / 应用重载 / serve 重启后渲染进程重建，槽位清零，用户打开过的会话卡片全部丢失，仅靠 `initial_loc()` 恢复一个初始会话。用户要求把打开的会话卡片持久化保存，窗口重开后恢复。

## 契约区

### 范围

- 将工作台打开的会话槽位持久化到渲染进程 `localStorage`：每个槽位的 source / env / session_id 及槽位顺序。
- 同时持久化当前布局列数（layout）与视图开关（view.show_time / view.compact）。
- 工作台初始化时读取持久化数据，恢复槽位顺序、布局与视图开关；每个恢复槽位重新订阅并拉取消息内容。
- 清空后持久化数据同步清空，重开为空工作台。

### 非范围

- 不持久化消息内容（重开后重新 query 拉取）。
- 不持久化消息选择状态、大纲抽屉状态。
- 不改主进程 / IPC / 磁盘文件存储。
- 不改变「最近会话 / 清空 / 视图」等既有交互语义。

### 风险与回退

- 风险：持久化 schema 无版本字段，未来结构变更难迁移；恢复流程与 `initial_loc` 并发可能重复打开会话。
- 回退：恢复逻辑仅读 localStorage，写入失败/解析失败回退为空工作台，不影响既有功能。
