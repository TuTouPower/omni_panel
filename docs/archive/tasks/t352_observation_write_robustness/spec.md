# Task spec

## 背景

observation-store 写入有三处问题：(1) 每次刷新逐观测单条 INSERT，无事务包裹，主进程同步 WAL 提交每行一次 fsync；(2) 非 stale 观测同键同 ts 重复插入无去重保护，`get_latest` 取行不确定；(3) 一次性数据清理（`DELETE ... kimi total_quota`）固化在迁移路径，每次打开 store 都执行。

## 契约区

### 范围

- observation-store 增加 `insert_batch(obs[])`，用 `db.transaction` 包裹（保留 per-obs 错误日志）。
- 非 stale 插入前同样按键删旧（或 INSERT OR REPLACE 语义），统一两种 stale 值。
- 迁移路径的一次性数据清理按 schema_version/迁移批次标记，仅执行一次。

### 非范围

- 不改留存策略（见 t343）。
