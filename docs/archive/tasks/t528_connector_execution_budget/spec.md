# Task spec

## 背景

p263 暴露连接器执行模型缺少资源契约：`isolated-process-runner.ts` 用单一 wall-clock 15s 硬杀整个连接器执行，`refresh-service.ts:249` 每个重试 attempt 又各给一次 `DEFAULT_TIMEOUT_MS`（3 次重试最坏 45s 连续打站），脚本无法感知截止、无法协作退出，宿主也不知道连接器发了多少请求、读了多字节。Muse 在全量分包扫描下串行发出 107 次 GET、累计 27s，被硬杀后只留下笼统 timeout，既不可诊断也无法区分「合法长任务」与「病态任务」。`ctx.http` 也无并发上限与请求预算，脚本只能各自写串行循环。

本 task 建立连接器执行的统一资源契约——预算 / 协作取消 / 计数 / 有界并发 / 资源回收——作为唯一执行模型，取代现有单值 timeout 与无预算路径。依审阅结论（A/B/C）：不留新旧双轨、不留运行时降级开关，能力落地即唯一模型，回退方式为 git revert。API 对脚本统一提供，宿主对全部连接器强制生效（不依赖脚本主动消费）。

本 task 同时是 t528→t529→t530 的契约真相源：完整连接器资源契约（含 t529 的发现缓存字段形态）在 t528 的 ADR 定稿，实施仍分 task 落地。

## 契约区

### 范围

- 单一执行预算模型取代单值 timeout：`Budget{total_ms, deadline, remaining()}`；从执行路径移除 `DEFAULT_TIMEOUT_MS`（`constants.ts:1`、`refresh-service.ts:249`、`runtime.ts:236`），不留单值兜底路径。
- 预算为 refresh 级、跨 retry 共享：一次刷新内的多次重试共享同一预算，不在每次重试重置。
- 宿主强制资源限制：per-execution 请求调度 / 限流 / 资源回收由宿主层强制；脚本裸循环亦被限流；不依赖脚本主动调用。
- 协作取消：`ctx.signal` / `ctx.deadline_ms` / `ctx.remaining_ms()` 始终提供（契约必选，非可选注入）；软截止触发协作退出，隔离宿主硬上限仅作兜底。
- 结构化取消原因与唯一结算点：到期与硬终止用错误码区分（`BUDGET_EXHAUSTED` / `TERMINATED`），不靠字符串匹配。
- 增量并发原语：可增量消费、可提前停止、允许后续请求继续执行（支撑 t530 命中即停后仍发用量请求）。
- 请求 / 字节计数：requests 为发起次数、bytes 为 UTF-8 解码后长度；经执行结果结构化回传，日志只记长度不记正文。
- `opts.timeout_ms` 只允许缩小不允许放大，最终取 `min(opts, remaining)`。
- 执行 generation / epoch：过期执行（如 force 绕锁导致的同实例并发）的结果不得覆盖较新执行的 cache / observation / runtime state，不得复活已失效缓存。
- 双进程语义统一：`utilityProcess` 与 `child_process.fork` 共用同一 budget / cancel 代码路径；`OMNI_IN_PROCESS_CONNECTOR` 仅作测试缝，不允许行为分叉。
- 审计含网络循环的内置连接器，仅在「请求数不确定 / 多」的脚本处补协作检查；其余连接器零脚本改动，但一律进入统一宿主限制。
- ADR：定稿完整连接器资源契约（预算、signal、计数、有界并发、发现缓存字段形态）。

### 非范围

- 不改 Muse 发现算法（t530）。
- 不实现发现缓存（t529），仅定稿其契约字段形态。
- 不把具体预算数值、并行度上限写成产品行为 AC（属技术选型）。
- 不改变现有观测 / stale / 失败账号语义。

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：脚本可查询本次执行的剩余预算，且单次 HTTP 请求的等待时间被收敛到不超过查询时刻的剩余预算（模拟延迟下请求在剩余预算内被中止）。
- [ ] AC-002：预算进入软截止时，脚本收到可感知的取消信号并协作退出；由此产生的错误以 `BUDGET_EXHAUSTED` 结构化标识，而非进程被杀或笼统超时。
- [ ] AC-003：宿主对本次执行的请求发起次数与读取字节数（UTF-8 解码长度）计数准确，经执行结果结构化回传；日志只含长度不含正文。
- [ ] AC-004：并发限制由宿主强制：使用增量并发原语的脚本在途请求数不超过上限；脚本裸循环同样被限流；执行完成或取消后不残留未结束的后台请求。
- [ ] AC-005：`opts.timeout_ms` 只能缩小不能放大，实际超时取 `min(opts, remaining)`；越界放大被忽略。
- [ ] AC-006：一次刷新的多次重试共享同一预算；预算跨 retry 连续消耗，不在每次重试重置。
- [ ] AC-007：软截止后脚本仍未返回时，隔离宿主以硬上限终止并结算，结果以 `TERMINATED` 标识；软、硬两种终止在结果中结构性可区分（非字符串匹配）。
- [ ] AC-008：同实例并发执行（force 绕锁）时，较早/过期执行的结果不覆盖较新执行的 cache、observation 与 runtime state，不复活已失效缓存。
- [ ] AC-009：不存在「无预算 / 单值 timeout」执行路径；全部连接器执行统一进入预算模型，`DEFAULT_TIMEOUT_MS` 不再出现在执行路径。
- [ ] AC-010：`utilityProcess` 与 `fork` 两种宿主下 budget / cancel 行为一致（同一代码路径）。
- [ ] AC-011：不消费新 API 的现有连接器在新执行模型下业务结果语义不变，全部现有连接器测试在新语义下通过（测试随新语义更新，不回退旧超时行为）。

## 上下文区

- 来源：p263（核实 2026-09-27：Muse 串行 107 请求约 27s，被隔离宿主 15s 硬杀）；审阅意见 A/B/C（执行模型去双轨、预算跨 retry、宿主强制限流、协议破坏性升级）。

### 有意不测

- 各连接器对软截止信号的处理质量：仅对审计出的网络循环脚本做针对性测试；其余以宿主强制限制覆盖。
- 跨平台进程杀灭细节（SIGKILL 时序）：以行为层「结构化区分软 / 硬终止」替代精确信号断言。

### 测试策略

- 单测：预算收敛（`min(opts, remaining)`）、跨 retry 共享、计数语义、宿主强制并发上限与取消后无泄漏、错误码区分。
- 集成：经隔离宿主（含 in-process 回退与 fork）跑只消费新 API 的测试脚本，断言软截止协作退出、硬兜底、结构化错误码、双进程一致。
- 并发一致性：模拟同实例两次执行，断言过期执行不覆盖新结果。
- 回归：现有连接器测试随新语义更新并全部通过；`DEFAULT_TIMEOUT_MS` 不再出现在执行路径（静态断言）。
- 新增测试缝须触达生产逻辑，不得只造平行桩。

### 风险与回退

- 风险：从单值 timeout 一次性切到统一预算模型会同时影响全部连接器；预算构造或取消语义若有回归，波及面为全部内置连接器。
- 回退：不设运行时降级开关；失败即 git revert。软截止信号采用「deadline 随载荷下发 + worker 本地派生 signal」形态，无宿主→worker 中途推信号的时钟竞态，从根上消除「脚本已协作退出但宿主仍硬杀」的竞态。

### 依赖与约束

- 前置：无。
- 约束：不得削弱隔离（连接器仍在隔离子进程执行）；新增 API 对脚本统一提供、宿主强制；日志不得记录 Cookie / 页面正文；不允许行为分叉的双进程路径。
- 平台：Windows / macOS / Linux 一致。
