# Task spec

## 背景

渲染进程中存在多处组件架构耦合、表单分支冗余与渲染性能问题：添加账号弹窗分支手写扇出且未校验空实例；图标系统三表重复维护且打包体积未优化；DevPanel 后台盲目高频轮询；`provider-usage.ts` 承担过多职责成为 766 行上帝模块；计算存在多重嵌套遍历；卡片重渲染由于内联闭包导致 memo 失效；整树 tick 刷新带来无谓开销。

## 契约区

### 范围

- `AddAccountDialog` 在 `local_cli` 扫描未完成时拦截实例创建；表单分支改造为 `FORM_REGISTRY` 数据驱动。
- 重构 `Icon.tsx`：合并三个零散注册表为单一来源，MiMo 图标改走资产文件，警告统一经由 logger，优化 vendor 图标打包体积。
- `DevPanelView` 根据状态自适应轮询并在页面不可见时暂停。
- 业务全局统一使用 `crypto.randomUUID()`；渲染层对远端字符串字段（label、tier、org）施加 64 字符上限与控制字符过滤。
- 将 `provider-usage.ts` 拆分为职责单一的子模块（分组、错误汇总、可见性、数据收敛），热路径采用 Map rank 与单遍遍历。
- 建立 `provider_registry.ts` 作为前端厂商元数据单一来源。
- 消除 Grok weekly 等重复判定；将 AccountKey 调整为强类型结构对象。
- 优化 `ProviderOverview` 与 `PopupView` 的渲染 memo，将相对时间 tick 订阅下沉至卡片局部，降低无谓重绘。

### 非范围

- 不修改现有 UI 设计规范（DESIGN.md）。
- 不破坏现有用户配置在前端的展现格式。
