# Task spec

## 背景

当前日志模块（`logging.ts`）在文件写入失败或清理失败时静默吞掉错误，导致磁盘满或权限异常时缺乏诊断信号；在日志尚未生成或丢失时导出日志会直接向用户抛出底层文件缺失异常（ENOENT）；日志的保留天数与容量上限等运维参数硬编码在代码常量中，无法灵活调整。

## 契约区

### 范围

- 日志写入与清理失败时增加 `console.warn` 告警与调用节流保护，防止递归触发日志。
- `exportCurrentLog` 增加源文件存在性检查，文件不存在时返回空数据或明确结果状态，杜绝裸异常抛出。
- 将日志保留天数（默认 7 天）、单文件/总容量上限（默认 50MB）等参数提取至配置系统。

### 非范围

- 不更改已有日志的单行格式规范与时区约定。
- 不引入重型外部日志框架。
