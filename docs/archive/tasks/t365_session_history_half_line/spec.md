# Task spec

## 背景

claude/kimi 增量提取缺 grok 已实现的半行容错：`extract_*_incremental` 直接 `buf.subarray(cursor.offset)` 从字节游标续读，游标无条件推进到文件 size。若上次读取落在写入半行时，半行 JSON 解析失败被跳过且游标越过它，该记录永久消失。grok 提取器（t216）已专门加了「半行容错 + 未完成尾行驻留行首」并有测试；kimi 另有 UTF-8 截断致字节 id 错位问题。

## 契约区

### 范围

- 把 grok 的行边界回退逻辑（lastIndexOf(0x0a) 找行边界、部分行不完整则从行首重读、尾行不完整则游标驻留行首）移植到 kimi 与 claude_code 增量提取。
- 处理 UTF-8 截断：增量读取前回退到最近行边界。
- 补与 grok-extractor.test.ts:115 等价的增量半行测试。

### 非范围

- 不改全量提取逻辑。
