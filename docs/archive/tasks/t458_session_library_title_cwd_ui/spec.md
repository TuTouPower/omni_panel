# Task spec

## 背景

查询层将提供独立 `title` / `directory` 过滤（t457），但会话库筛栏仍只有「标题/目录/会话 ID」混搜框，人无法按标题与工作目录分别约束。本 task 让桌面与 web 会话库 UI 接上同一套条件。

## 契约区

### 范围

- 会话库筛栏增加独立「标题」「工作目录」输入，值分别作为查询的 `title`、`directory`。
- 与已有日期范围、Agent、排序、分页 AND；请求空值时不带对应参数。
- 勾选「包含消息内容」时，标题/目录等过滤仍约束候选，再扫正文。
- 「清空筛选」同时清空标题与工作目录。
- 桌面与 web 共用会话库组件，行为一致。
- 现有混搜框、日期、Agent 芯片、排序选项、网格/列表、预览与 dock 保留。

### 非范围

- 查询层 `title`/`directory` 实现（t457）。
- 改网格/列表卡片信息结构、预览抽屉、SelectionDock、打开工作台语义。
- 新增排序字段或改分页页大小。
- skill / `cli.json`（t459、t460）。

- [ ] AC-001：筛栏有独立标题输入；只填标题时，列表请求带 `title` 且不因会话 directory 或 id 含该串而展示该会话。
- [ ] AC-002：筛栏有独立工作目录输入；只填目录时，列表请求带 `directory` 且不因会话 title 或 id 含该串而展示该会话。
- [ ] AC-003：标题、工作目录、日期范围、Agent、排序同时设置时，列表与「加载更多」请求都带上这些条件（AND），分页不丢条件。
- [ ] AC-004：清空筛选后标题与工作目录输入为空，随后列表请求不再带 `title`/`directory`。
- [ ] AC-005：勾选「包含消息内容」并提供正文关键词时，正文搜索候选过滤仍带当前标题与工作目录；被这两项排除的会话不出现在结果中。
- [ ] AC-006：web 会话库与桌面会话库对 AC-001～AC-005 的筛选请求字段与结果约束一致。

- web 与桌面：同组件则断言两路 bridge 都把字段传到查询；不重复测 store SQL（归 t457）。
