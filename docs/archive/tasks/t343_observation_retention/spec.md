# Task spec

## 背景

`observation-store.ts` 的 `prune()` 无任何生产调用方，`cacheMaxMb` 配置无消费者，observations 表无界增长：每次成功刷新都为每个 metric 插入新行，长期运行下行数单调增长，`query_trend_series`/`list_latest_by_provider` 等查询成本随行数线性劣化，磁盘占用同步增长。

## 契约区

### 范围

- 在 config-store 或 scheduler 中接入留存策略：启动与每日定时调用 `prune(now - 90d)`（或按 cacheMaxMb 折算行数预算）。
- 把 `data_section` 的 cacheMaxMb 设置真正接到该逻辑（或明确弃用该设置并移除 UI 项）。

### 非范围

- 不改 insert 去重/事务（见 t352）。
- 不做按 metric 差异化留存（超范围）。
