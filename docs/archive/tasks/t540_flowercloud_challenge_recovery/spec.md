# Task spec

## 背景

来源 p272：用户要求花云后台自动完成验证并恢复用量采集。2026-09-30T18:45:19+08:00 起运行生产等价隐藏 Electron 探针，确认当前环境收到要求人工勾选的 Cloudflare 交互挑战；40 秒内未获得 cf_clearance。当前任务没有可验证的自动通过路径，不能把延长等待或修改提示视为完成用户目标。

## 契约区

### 范围

- 查明已有登录会话为何重新遭遇挑战；在站点允许自动验证的场景中修复后台脚本执行或会话复用问题；失败原因忠于证据。

### 非范围

- 自动破解、代点 CAPTCHA、人机信号伪造、规避服务端风控；修改当前用户数据或重启当前 app。

### 验收标准

<!-- 规范（门禁必留，不得删除） -->

只写可观察、可独立验证的行为；每条使用稳定且不复用的 `AC-NNN`。需真实部署或人工环境验证时在编号前加 `[deploy]`。技术选型不作为行为 AC。

<!-- /规范 -->

- [ ] AC-001：在已确认支持自动验证的真实会话场景中，无人工操作、无前台窗口即可采集新用量；必须证明快照时间与用量来自本轮页面，旧快照或仅 Cookie 存在不算成功。
- [ ] AC-002：自动验证未完成时提示不武断认定必须人工；确认交互挑战后提供准确原因，失败保留旧用量与真实新鲜度。

### 可测试性声明

<!-- 规范（门禁必留，不得删除） -->

逐条说明不可自动测试的 AC 及替代验证；全部可测则写“全部 AC 可自动测试”。

<!-- /规范 -->

- AC-001：真实 Cloudflare 结果由外部站点决定，不能用固定 HTML 桩代替；需支持自动验证的真实会话和本机黑盒验证。AC-002 可用生产分类函数与会话、调度集成测试验证。

## 上下文区

- 来源：p272、t535、d063（2026-09-30 核实：隐藏窗口也能直接出现交互挑战，旧 finding 关于 reveal 导致挑战升级的因果结论不成立）

### 有意不测

- 代点或破解交互验证码：不属于可执行实现范围。

### 测试策略

- 先验证真实自动通过机制，再建立触达生产逻辑的失败用例；验证会话复用、分类文案、旧观测保护与生命周期。执行时按 testing.md 完成相关测试、类型、lint、构建和独立 review。

### 未知契约清单

<!-- 规范（门禁必留，不得删除） -->

未核实的外部契约标为 `UNVERIFIED-BLOCKING` 或 `UNVERIFIED-SPIKE`；核实后改写为结论和验证方式。无则写“无”。

<!-- /规范 -->

- 真实站点当前是否提供无需人工的验证恢复路径：UNVERIFIED-BLOCKING。当前探针为新建隔离会话，收到交互挑战；不能据此证明用户既有登录会话同样不可自动恢复，也不能自动解决探针 CAPTCHA。须取得站点支持的自动访问方式或确认可复用有效登录会话后再实施自动恢复。

### 风险与回退

- 风险：站点继续要求人工交互，自动恢复目标无法达成；当前 Cookie 存在与客户端未过期不等于服务端接受；预期的 PAT 401、DNS/TLS 探测失败不能直接归为根因。
- 回退：保留当前实现与登录凭据、保留旧观测；不扩大重试或宣称修复，不执行没有证据支持的方案。

### 依赖与约束

- 主仓存在并行会话的 SettingsForm 等无关改动，必须保留。生产实施需登记独立 worktree。隐藏探针不抢焦点；任何前台验证或 package/reload 需明确许可。

### Finalization 时更新的 blueprint

- `docs/blueprint/decisions.md` 与 `docs/blueprint/architecture.md`：根据最终验证事实修订挑战与会话恢复策略，纠正显示窗口与交互挑战的因果推断。
