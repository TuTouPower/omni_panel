# Task spec

## 背景

日志系统性能/健壮性缺口：(1) 文件 transport 每条日志一次 stat + 一次 appendFile（open/write/close），写放大明显；(2) 日志段数达上限后写入被静默跳过，持续错误期间诊断信息丢失；(3) `scrub_meta` 每次 emit 双重序列化；(4) 高频轮询/渲染日志路径成本累积。

## 契约区

### 范围

- 文件 transport 复用持久 fd 或批量缓冲（如每 100ms 合并写），size 检查改为缓存值周期 stat。
- 段数达上限后按写入条数周期性重新 warn（或降级丢弃最旧段）。
- scrub 改单趟字符串替换或基于 serialize_meta 结果单次序列化。

### 非范围

- 不改日志级别/内容语义。
