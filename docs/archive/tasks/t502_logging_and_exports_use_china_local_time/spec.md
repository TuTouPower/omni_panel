# Task spec

## 背景

在非 UTC 零时区（如系统本地时区为 UTC+8 中国标准时间）下，00:00~08:00 期间日志文件按 UTC 日期切分，写入了前一天的日志文件（例如 2026-09-18 凌晨 03:23 产生的日志被记录在 `app-2026-09-17.log`）；且日志条目内的 `ts` 也是 UTC 零时区时间戳（形如 `...Z`）。更严重的是，常驻桌面进程在启动时打开一个写入 fd 长期复用，若仅在启动时计算文件名而不做写时跨天检测与 fd 轮转，跨过午夜 00:00 后常驻进程仍会持续写入昨天的旧文件；此时调用 `exportCurrentLog` 按当前时刻查找新文件，会导出一个空文件，造成全天数据静默丢失！此外，`src/main/core/local-api/server.ts:1056-1058` Web 日志导出硬编码以 UTC 日期拼接 `app-${date}.log` 查找磁盘文件，导致 00:00~08:00 期间 Web 端导出直接 404；前端与桌面端导出文件名散落在 6 处硬编码 UTC，亟待统一。

## 契约区

### 范围

- `src/shared/lib/local-time.ts`（新建纯函数共享 helper）：
    - `get_local_date_string(date?: Date): string`：返回系统本地时区的 `YYYY-MM-DD` 字符串；
    - `format_local_iso(date?: Date): string`：返回带本地时区偏移的 ISO 时间戳字符串（如 `2026-09-18T03:23:02.416+08:00`）。
- `src/main/core/logging.ts`：
    - `getLogFilePath` 改用 `get_local_date_string` 获取本地年月日；
    - 写入逻辑增加写时跨天检测：写日志时若比对发现当前本地日期与当前打开 fd 对应的日期不同，则主动关闭旧 fd、重算日志路径并重新打开新一天的日志文件 fd（跨午夜自动轮转）；
    - `exportCurrentLog` 与写路径当前的活跃日志文件保持严格同步，确保跨天后导出的是包含最新写入的日志；
    - `cleanupOldLogs` 基于文件 `mtimeMs` 和当前时刻 `Date.now()` 滚动计算，与文件名日期无关，无需逻辑修改，仅验证跨天滚动时不误删。
- `src/main/core/local-api/server.ts:1056-1058`：
    - Web 日志导出接口统一调用 `get_local_date_string` 查找当天日志文件路径与下载推荐名，与 `logging.ts` 保持绝对一致，杜绝 00:00~08:00 导出报 404。
- `src/web/usageboard-web.ts:396, 668-669`：
    - 前端 Web 桥接中配置导出与日志下载的默认保存文件名改用 `get_local_date_string`。
- `src/shared/lib/logger.ts`：
    - 日志条目顶层 `ts` 字段默认时间戳输出带本地时区偏移的 ISO 格式时间戳字符串；
    - 结构化元数据（`serialize_meta`）中的机器日期显式保留原有格式（有意保留 UTC），避免破坏机器下游分析。
- `src/main/ipc/log-ipc.ts` 与 `src/main/ipc/config-ipc.ts`：
    - 桌面端日志导出与配置备份的默认保存文件名中的日期改用 `get_local_date_string`。
- `src/main/cli/background_serve.ts:128`：
    - 后台 serve 日志命名改用本地时区时间（对文件名中的冒号与加号做合法字符转换）。
- 补齐与改造测试：
    - 改造现存 `tests/unit/main/logging.test.ts:150, 159-163`，消除硬编码 `toISOString().slice(0, 10)` 的假定，使不同时区 CI 均能通过；
    - 编写常驻进程模拟跨午夜写入 fd 自动轮转测试，验证旧文件关闭、新文件创建及数据归属；
    - 覆盖 `local-time.ts` helper 单元测试与 Web 导出端点对齐测试。

### 非范围

- 不修改 `logging.ts` 的 `cleanupOldLogs` 核心清理算法（已有按 mtimeMs 的逻辑已自洽）。
- 不回写或修改已有磁盘上的旧日志文件内容。
- 不改变结构化元数据（`serialize_meta`）中机器消费的 UTC 格式；有意保留 `startedAt`、`exportedAt` 等机器时间戳为 UTC。
- 不改变日志等级（DEBUG/INFO/WARN/ERROR）与日志文本的核心字段结构。

- [ ] AC-001：`getLogFilePath` 生成的日志文件名日期（`app-YYYY-MM-DD.log`）与当前系统本地时区日期严格一致；常驻进程在本地时间跨过午夜（00:00）写入新日志时，自动关闭昨天的旧文件 fd、创建并打开新一天的本地日期日志文件，不再向旧文件追加。
- [ ] AC-002：`exportCurrentLog` 导出的日志文件与写路径当前活跃文件同步，跨午夜后导出包含完整的当日最新日志内容，杜绝导出空文件。
- [ ] AC-003：日志输出顶层 `ts` 字段格式包含系统本地时区偏移（例如中国时区输出形如 `2026-09-18T03:23:02.416+08:00`），直观反映本地真实时刻；结构化元数据（meta）中的机器日期保持 ISO 原样。
- [ ] AC-004：Web 端日志导出（`server.ts:1056-1058`）在跨过本地午夜后能正确命中当日本地日志文件流式返回，不报 404；桌面端与 Web 端各导出界面的默认文件名日期均与本地日期严格一致。
- [ ] AC-005：改造已有 `logging.test.ts` 中针对 UTC 日期的旧断言，并新增常驻进程模拟跨午夜写入 fd 自动轮转测试、Web 导出端点对齐测试以及多时区偏移 helper 纯函数单测。

## 上下文区

- 来源：p252（2026-09-18 核实：多处硬编码 UTC 日期致使 00:00~08:00 404；经 OpenCode Muse-Spark-1.3 审查揭露常驻进程未做写时跨天检测将导致跨天后写旧文件、导出空文件的严重阻塞隐患）。

### 有意不测

- 生产环境真实时钟跨天（测试通过可注入 `now` 的纯函数及 mock 定时器/推进时刻验证）。

### 测试策略

- 针对 `local-time.ts` 纯函数编写覆盖中国时区（UTC+8）、西区及零时区的纯单元测试。
- 在 `logging.test.ts` 中通过注入时间推进构造 `23:59:59 -> 00:00:01` 跨午夜两次写入，断言旧文件被正确关闭、新文件生成，且写入分别进入对应的文件。
- 在 `server.test.ts` 中验证日志导出端点对本地日期的解析与文件命中。

### 风险与回退

- 风险：下游日志解析器若存在严格匹配 `/Z$/` 正则可能失效。经对 `src/` 全量排查，前后端无任何 `/Z$/` 或 `endsWith("Z")` 强依赖，主流 `Date.parse` 与 `new Date()` 均原生支持标准时区偏移（`+08:00`），变更向下兼容。
- 回退：回滚时间戳与文件名格式化改动。
