# Task spec

## 背景

当前单元与集成测试存在多处测试假绿、弱断言和门禁宽松问题：部分代理测试使用全匹配正则掩盖了未预期的失败；部分连接器测试 mock 了自身的阈值算法而未直达生产实现；IPC 测试全量 mock 缺少参数和错误映射断言；并发测试采用宽泛的不等式断言；覆盖率门禁阈值过低；全局 60s 超时掩盖了偶发挂起缺陷。

## 契约区

### 范围

- 重构弱断言测试：代理测试改为本地桩状态精确断言；OpenCode 测试直达 `ctx.status` 生产逻辑；IPC 测试验证错误码映射与参数边界；并发测试改为精确等式断言（同实例为 1，不同实例为 2）。
- 补充测试覆盖：添加 Grok Bot checksum 已知向量回归用例、Muse 异常数据流测试、OAuth 并发取消与重入用例。
- 将 `vitest.config.mts` 的全局超时从 60s 调整为 15s，特殊长测试显式单独配置超时。
- 依据全仓实际代码覆盖率重新设定分目录覆盖率基线门禁（ratchet 机制）。

### 非范围

- 不改变生产环境的业务逻辑实现。

### 风险与回退

- 风险：缩短全局超时可能导致极少数慢速测试偶尔报超时（flaky）。
- 回退：对确有慢 IO 依赖的少数集成测试显式单独声明超时（如 `{ timeout: 30000 }`）。
