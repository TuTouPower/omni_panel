# Task spec

## 背景

Grok Bot 认证与连接器全链路存在多项安全与稳定性漏洞：PKCE verifier 在 IPC 与渲染层明文传输；并发登录轮询产生孤儿任务；刷新缺乏去重导致竞态失效；401 未抛出导致无法触发换票重试；凭据保存与登出非原子；浏览器拉起失败空转 180s；表单组件重入与未清理卸载；缺失后台定时刷新与 Token 轮换支持。

## 契约区

### 范围

- 重构 PKCE 认证流程，verifier 仅在主进程驻留，IPC 仅传 `login_id`。
- 修复并发登录孤儿轮询，增加 active cancels 冲突拦截与清理；IPC `timeout_ms` 钳制到 10s..600s。
- 为 `refresh_now` 实现基于 instance 的 Promise 去重机制。
- 连接器 401/403 明确抛出会话失效异常，驱动调度器执行 `oauth_refresh`。
- 安全派生 `account_id`，修复 checksum 计算溢出，增强 JWT 解析健壮性。
- 为 HTTP 增加超时（15s）、优化重试退避策略与 jitter、防范服务端原始错误暴露。
- 增强 Vault 写入错误捕获与原子补偿，登出时并行清理两项凭据。
- 修复 `GrokBotPkceForm` 组件生命周期、卸载取消机制、重入守卫与表单校验。
- 定义 `GrokBotErrorCode` 判别联合与统一映射。
- 实现后台定时刷新机制与 Refresh Token 轮换生命周期管理。

### 非范围

- 不更改 Grok 官方服务端的 OAuth 端点契约。
- 不影响除 Grok Bot 以外的其他连接器认证实现。

- [ ] AC-001：发起 PKCE 登录后，渲染进程与 IPC 消息仅接收 `login_id`，内存与传输链路中无 code verifier 明文。
- [ ] AC-002：同一实例再次发起登录时，前一次轮询被安全终止或新请求返回冲突，主进程无孤儿轮询驻留。
- [ ] AC-003：并发调用同一账号实例的 token 刷新时，仅发出一次底层网络请求，多个调用方复用同一 Promise 结果。
- [ ] AC-004：连接器请求返回 401 时抛出会话失效错误，调度器捕获后成功执行 `oauth_refresh` 流程。
- [ ] AC-005：拉起浏览器失败时立即返回明确错误，前端提示用户并直接中止登录轮询。
- [ ] AC-006：Vault 保存凭据失败时抛出错误，界面呈现真实失败原因；登出操作完整清除 access 与 refresh token。
- [ ] AC-007：IPC 传入非法或超出 10s-600s 范围的 `timeout_ms` 时返回参数校验错误。
- [ ] AC-008：`GrokBotPkceForm` 卸载时主动取消正在进行的认证轮询，且账号名去除首尾空格后回退默认值。
- [ ] AC-009：后台定时器在凭据临期时自动发起换票，成功写入新 Token 并在失效时提供明确告警。

### 风险与回退

- 风险：若主进程缓存的 login_id 发生泄漏或超时未清理，可能累积内存。
- 回退：设置显式 TTL 清理定时器与有限集合上限；如遇未预期错误可回滚。

### 依赖与约束

- 依赖 Vault 安全存储模块；遵循 Electron IPC 传输规范。
