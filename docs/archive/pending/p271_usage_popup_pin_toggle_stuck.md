# p271 用量 popup 置顶不收 + 切 Space 后托盘点击无反应

- 现象：macOS 用量弹窗（`mainPanelMode=popup`）两条可观察行为与预期不符。（1）`窗口始终置顶`（`pinToTop=true`）打开后，弹窗出现后点击别处不自动收起，常驻不消失；用户期望点外部收起（`window-management.md` popup=失焦隐藏，设置行无“钉住常驻”说明）。（2）不管 `pinToTop` 开关，只要弹窗开着未关，经 `Command + Tab` 切到他应用/Space 后再点托盘图标，弹窗不出现、体感“没反应”；再点一次才回来。
- 影响：macOS 下 popup 主路径不可用；多 Space/全屏工作流必现第（2）条；第（1）条钉住用户每次需手动关。波及左键 `tray.on("click")` 与菜单内 `TRAY_OPEN_PANEL → tray.emit("click")` 同一 toggle 路径；`activate`/agent/history/dev 走 `open_or_focus` 不受影响。
- 根因：产品缺陷（非环境/配置），两层叠加，已用 `.scratch` 复现。（a）`pinToTop` 与自动收起绑死：`src/main/core/main-panel/main-panel-controller.ts:55-64` `should_hide_popup_on_outside_focus` 含 `!pin_to_top`，`:322-327` `blur` handler 首行 `if (pinToTop===true) return`，`82-96` `handle_browser_window_focus` 同条件豁免；调用方 `src/main/index.ts:1534-1546` 透传 `pin_to_top`。p258 遗留“pin 开启行为待定”被实现侧直接落成豁免，与 spec 失焦隐藏冲突。（b）toggle 用全局 `isVisible()` 做切换条件，Space/focus 盲区：`main-panel-controller.ts:398-410` `open_or_toggle` 见 visible 即 `hide()`；Cmd+Tab 切走不走进程内 `browser-window-focus`，NSPanel（`type:panel` + `setVisibleOnAllWorkspaces(visibleOnFullScreen)` + `showInactive`）全局仍 visible，新 Space 第一击误走 `hide()`（即 p253 归档条目复发；t503 只修了展示期提权/跟随，未修 toggle 条件）。已确认同类位点：`src/main/index.ts:1456-1464` tray 左键同一 `open_or_toggle`；`1370-1373` `TRAY_OPEN_PANEL` 转发同路径；`1467-1474` 右键 `trayMenuWin.isVisible()` 切换同构（菜单窗已有跨 Space 属性但切换仍反转）。吃不准单列：floating 模式同函数 toggle 在跨 Space 下同样反转，是否算 bug 待产品定，不并入修复范围。
- 测试缺口：`tests/unit/main/main_panel_controller.test.ts` 把当前错误行为锁死 + 缺跨 Space 用例。（1）`:733-742` `pinToTop 钉住→豁免不收`、`:786-790` blur 钉住不收、`:871-880` t536 钉住豁免三处断言豁免为正确，属假绿锁 bug；若解耦 pin 只管层级不管收起，三处须改。（2）toggle 只测同 Space（`:276-284` 可见即 hide、`286-300` 隐藏重开），无“visible 但不在当前 Space/未聚焦时应 show+提权+重锚”用例；`index.ts` tray 接线无单测。应补：controller 层——pin=true 点外部仍 hide（含 blur 与 `should_hide`），toggle 在 visible-but-unfocused/stale-Space 时走 `show_panel`（重锚 `position_popup` + `elevate_for_show` + `setVisibleOnAllWorkspaces` 重申），不走 hide；tray 转发路径同断言；真机 Cmd+Tab/双全屏仍标 `[deploy]`。
