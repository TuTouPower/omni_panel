# p266 Muse 动态 Action 发现锁定错误候选，真实回归与验收证据不足导致再次失败

- 类型：bug
- 来源：2026-09-28 用户反馈“用量获取已经改动很多次，这次又报错，为什么没有根治”，要求详细登记 pending todo；本会话只读诊断、源码及历史 task 审计。
- 现象：目标 `fetchSubscriptionAction` 仍存在于当前网站分包，但生产连接器发现路径报 `DISCOVERY_EMPTY`；随后重试耗尽共享执行预算。

- 测试缺口：缺少错误候选先到、正确候选后到、完成顺序置换的真实分包关系回归；107 分包预算测试实际第 4 包立即命中，没有约定延迟。
- 线索：本条保留本会话实测摘要与复现步骤；本次探针在终端内存执行，未保存脚本或原始响应。旧 `.scratch/muse_timing_probe.mjs` / `.jsonl` 属 p263 历史诊断，不能当作本次复现产物。
- 处理：t534
- 关联：p263 已由 t530 闭环归档；本条记录后续复发，不改归档条目。相关任务 t525、t528、t529、t530。

### 已验证与未验证边界

- 已验证：当前页面含可识别目标；首候选无目标；当前算法不遍历后续 settings 候选；应用日志与探针发现失败一致。
- 已验证：`src/main/core/connector/execution-budget.ts` 中 pool 的 completed 队列由 worker 完成即 push，再按完成顺序 yield；源码因此存在响应完成顺序影响首候选选择的机制。
- 未验证：不同真实网络响应顺序下的成功率、当前持久化缓存具体内容、成功发现后的本次真实用量 POST 与解析结果、完整运行包一致性与修复后的真实刷新。
- 本次未执行用量 POST，不能宣称会话已通过完整认证验证；现有证据也不支持把本次发现失败直接归为登录失效或要求重新登录。
- 首次失败约 6.95 秒即可发生，不需要先耗尽 15 秒预算；后续预算耗尽是重试后的结果，不能把这次主因继续描述为纯下载超时。
- 页面内部编译结构会变化；模块数字仅用于这次回归关系，不应硬编码成长期匹配条件。

## 根因机制

生产位点：`connectors/muse/connector.ts` 的 `resolve_dynamic_action_ids()`。

1. 首页脚本列表排序后通过 `ctx.pool.map(..., { concurrency: 4 })` 下载；消费顺序是完成顺序，不是稳定 URL 顺序。
2. 遇到 `HatchSettingsDialogContent` 链路后，仅在 `!settings_module_id` 时赋值。首个匹配锁定候选，后续候选被忽略。
3. 首页未直接找到目标时，只查该候选模块的 `Promise.all` 异步清单；对应分包没有目标则结束发现，未继续验证其他候选。
4. 本次 87 次 GET 与“首页 + 85 个首屏分包 + 错误候选的 1 个分包”一致，结合代码推断锁定 `273187`；正确目标已实测位于 `862035` 关联分包。目标正则本身能识别目标，因此本次不是 Action 不存在或目标正则完全失效。
5. 并发缩短下载时间，缓存减少重复发现，两者都没有建立“候选必须验证成功，否则继续搜索”的正确性条件。首候选假设仍会在冷缓存等场景暴露。

分类：产品实现缺陷，叠加测试代表性与验收报告问题。不能仅归因于上游网站发布频繁。

## 后续修复与验收建议

具体设计由修复 task 确定，建议约束如下：

1. 脱敏保存真实首页、候选引用、模块清单与目标分包最小关系；保留足以复现错误选择的结构，不保存 Cookie、账号、完整私人页面或无关响应。
2. 对所有合理候选逐个或有界并发验证；候选不含目标时继续回退。结果不能由请求完成顺序决定，不能仅把某个模块 ID 写死、调换排序或更新 Action 常量。
3. 回归触达生产连接器与真实 pool：至少两个候选，错误先到、正确后到，以及响应顺序置换；断言准确选择目标、完成用量阶段并产出期望观测。
4. 以可控时钟/网络桩模拟首页约 1.3 秒、107 分包均值约 250ms；覆盖早命中、晚命中、多候选、无命中、单包 404、慢包。验证总预算、并发上限、命中或取消后停止拉取，以及 POST 具备可用预算。
5. 覆盖冷缓存、同签名复用、部署/后部 URL 变化、服务端拒绝旧 Action 后失效重发现；避免缓存掩盖发现错误。保留原认证与响应解析行为回归，不把旧预期直接改成当前失败输出。
6. 结构化诊断应包含阶段、候选数量/验证结果、扫描数、耗时和剩余预算；区分发现为空、请求失败、Action 失效、会话失效及预算耗尽。日志不得包含凭据或完整页面。
7. 审视合理重试：同一错误候选重复扫描通常不能自愈；共享预算下避免无效重试耗尽全部余量，网络瞬时失败与确定性解析失败分别处理。
8. 自动化验证与真实打包验收分开记录。涉及打包、重启或弹窗的验证须按项目规则另获许可；未经真实验证，仅报告自动化路径结果及未验证项。
9. 验收逐条附对应场景和证据；缺失或待核实项明确列遗留，不再写“全部解决”。不能承诺永久兼容上游任意编译结构变化。
