# d059 Command Code CLI 会话 JSONL 格式（每轮用量 + 会话历史单源）

- 来源：s037（2026-09-14）；2026-09-14 复核修正（累计语义结论被推翻，见「修正」）
- 结论：Command Code CLI（`cmd` v1.53.1）会话落盘在 `~/.commandcode/projects/<encoded-cwd>/<session-id>.jsonl`，单一文件同时承载会话正文与 token 用量，可直接支撑会话面板 + 代理面板。字段映射：文件首行 `type:"session"`（`id`=session-id=文件名、`cwd`、`timestamp` ISO8601）；此后每行 `type:"message"`，正文在 `message.content[]`（`{"type":"text","text"}` user/assistant 正文、`thinking`、`tool_use{id,name,input}`、`tool_result{tool_use_id,content}`）；assistant 行顶层带 `usage{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,costUsd}`、`model`、`effort`。user 消息分两类：`message.meta.source=="user"` 为真人输入（纯 text），`source=="tool"` 为工具结果回填（tool_result 块）。
- 关键语义（决定统计正确性，**已修正**）：`usage` 是**每轮单次请求用量（非累计）**。证据：逐行 `outputTokens` 在 193/202 会话中出现回落、`costUsd` 在 199/202 会话中出现回落；累计量不可能下降，故 `outputTokens`/`costUsd` 必为每轮值。`inputTokens` 在 198/202 会话逐轮递增（4/202 仅小幅回落 ≤10%），提升的是**每轮 prompt/上下文窗口大小**（≈ 上一轮 output + 本轮用户/工具输入），不是会话累计消耗。因此**正确口径是把每轮 usage 直接相加**（每轮都是独立一次请求的计费），**不得做累计差分**。
- 修正（2026-09-14 复核，推翻原 s037 结论）：原 d059 断言「`usage` 是累计值、须同 codex 做累计差分（`fresh=input-cacheRead` 汇总约 31.7M/output 11.4M/cost $15.24）」。复核证明该假设错误：按累计差分处理会把 `outputTokens`/`costUsd` 近乎归零，并使 `inputTokens` 因差分与求和同值（求和 1.243e9、差分后 1.243e9 量级一致，恰因 input 近似单调累积上下文）而掩盖错误。正确语义为每轮独立用量，逐行相加：全库 202 会话 `inputTokens` 合计 1.243e9、`outputTokens` 11.41M、`costUsd` $15.24；项目 `tokens=input+output` 口径下约 1.255e9。`inputTokens` 含缓存命中，`fresh=inputTokens-cacheReadTokens` 的归一仍适用于「缓存率」展示（`cacheReadTokens` 为 `inputTokens` 子集，202/202 无 `cacheRead>input`），与 `claude-reader`/`codex-reader` 的 `inp>=cache_read` 守卫一致；但**不改变「每轮值直接相加」这一归因方式**。
- 证据：只读探针 `docs/spikes/s037_commandcode_token_session_source/code/probe_commandcode.py`（2026-09-14 本机实测）。202 个 jsonl（=202 会话，无缺 usage 文件），7713 条 usage 行全在 `message.role=assistant`，202/202 文件名 == session id；时间范围 2026-09-11→09-13；内容块分布 text 5271 / thinking 7280 / tool_use 12324 / tool_result 12324；模型 `deepseek/deepseek-v4.1-flash`。旁证 `~/.commandcode/projects/<proj>/<id>.meta.json`（title/model）、`<id>.checkpoints.jsonl`（turnNumber/prompt 摘要）、`~/.commandcode/history.jsonl`（跨会话 prompt 历史）。复核探针（一次性，未入库）：逐文件字段回落计数与逐轮数值抽样，见「影响」。
- 影响：Command Code 可按三件套模式接入（token-stats reader + session-history extractor + 接线）。**reader 按每轮 usage 直接相加归因**（不差分；`input` 归一 `inp-cacheRead` 仅用于缓存率，`cacheWriteTokens` 实测恒 0，`costUsd` 每轮值相加）。`inputTokens` 逐轮小幅回落处（4/202，≤10%）按每轮原值直接计入，不做归零/分段基准。extractor 正文取 `content[]` 的 text，user 需过滤 `meta.source=="tool"`、assistant 过滤 thinking/tool_use。恢复命令实测：`cmd --resume <session-id>`（`cmd --help` 原文 "Resume a conversation by id or name"）。
- 现状：有效（语义部分经 2026-09-14 复核修正；正文路径/字段/恢复命令部分维持不变）
- 遗留：`cmd` 版本升级后 `usage` 字段语义是否变化需重核；`inputTokens` 的 4 次回落归因（上下文裁剪 vs 计数重排）未定，按每轮原值计入即可，不影响口径正确性。
