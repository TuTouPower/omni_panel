# d059 Command Code CLI 会话 JSONL 格式（token 累计 + 会话历史单源）

- 来源：s037（2026-09-14）
- 结论：Command Code CLI（`cmd` v1.53.1）会话落盘在 `~/.commandcode/projects/<encoded-cwd>/<session-id>.jsonl`，单一文件同时承载会话正文与 token 用量，可直接支撑会话面板 + 代理面板。字段映射：文件首行 `type:"session"`（`id`=session-id=文件名、`cwd`、`timestamp` ISO8601）；此后每行 `type:"message"`，正文在 `message.content[]`（`{"type":"text","text"}` user/assistant 正文、`thinking`、`tool_use{id,name,input}`、`tool_result{tool_use_id,content}`）；assistant 行顶层带 `usage{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,costUsd}`、`model`、`effort`。user 消息分两类：`message.meta.source=="user"` 为真人输入（纯 text），`source=="tool"` 为工具结果回填（tool_result 块）。
- 关键语义（决定统计正确性）：`usage` 是**累计值**而非增量——逐行 `inputTokens` 单调递增（中位会话首轮 21.5k→末轮 196k，峰值 709k），`cacheReadTokens` 是其中的缓存命中子集，`cacheWriteTokens` 实测恒 0。不可逐行相加求和（会重复计历史）。正确口径同 codex：按文件内累计差分取增量为该会话 token 用量；`fresh = inputTokens - cacheReadTokens`（OpenAI 含缓存语义，与项目 `claude-reader`/`codex-reader` 的 `inp >= cache_read` 归一化一致）。全量 202 会话直接相加 `inputTokens` 会得到 1.24e9 的虚高值，差分后 fresh 约 31.7M / output 11.4M / cost $15.24。
- 证据：只读探针 `docs/spikes/s037_commandcode_token_session_source/code/probe_commandcode.py`（2026-09-14 本机实测）。202 个 jsonl（=202 会话，无缺 usage 文件），7713 条 usage 行全在 `message.role=assistant`，202/202 文件名 == session id；时间范围 2026-09-11→09-13；内容块分布 text 5271 / thinking 7280 / tool_use 12324 / tool_result 12324；全库仅 4 次 `inputTokens` 下降（分段差分基准要处理）；模型 `deepseek/deepseek-v4.1-flash`。旁证 `~/.commandcode/projects/<proj>/<id>.meta.json`（title/model）、`<id>.checkpoints.jsonl`（turnNumber/prompt 摘要）、`~/.commandcode/history.jsonl`（跨会话 prompt 历史）。
- 影响：Command Code 可按 codex 三件套模式接入（token-stats reader + session-history extractor + 接线）；reader 必须做累计差分且处理 4 次回落；extractor 正文取 `content[]` 的 text，user 需过滤 `meta.source=="tool"`、assistant 过滤 thinking/tool_use。恢复命令实测：`cmd --resume <session-id>`（`cmd --help` 原文 "Resume a conversation by id or name"）。
- 现状：有效
