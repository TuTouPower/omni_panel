# d065 scrubber 多分组扫描的热路径量级注脚

- 来源：审阅采纳 A16（2026-09-30，代码走读 + 常量核算，未实测 profiling）
- 结论：`scrub_text`（`src/shared/lib/logger.ts:95-135`）每行日志对每个注册分组做一次全文 `exec` 并收集区间、排序合并；注册值达数千（上限 10000，组大小 500 → 最多 20 组）时每行约 20 次正则扫描。为长凭据优先与跨组重叠合并所必需，取舍正确。
- 证据：`SCRUB_GROUP_SIZE=500`、`MAX_SCRUB_VALUES=10000`、`MAX_SCRUB_VALUE_LENGTH=8192`（超长整页 DOM 挡在注册表外，故不会为 8KB+ 文本构造巨型交替式）；排序 `O(n log n)` 以命中数为 n，有界。
- 影响：高频 debug 日志 + 大注册表场景若出现可观测的日志开销，先看此条再决定是否优化（如按调用方分表、采样）；当前无需改代码。
- 现状：有效
